Where a custom CMS would actually beat WordPress

Four concrete advantages of moving /lp-* generation to a flat-file, agentically-managed system — evaluated specifically against what's holding back AI-search visibility and conversion today.

01

Clean output for GEO

Elementor renders heavy widget/wrapper markup, inline CSS/JS, and multiple plugins competing to inject schema — Rank Math, AEOmatic, and whatever the theme adds on top. A flat-file system gives us full, uncontested control of the <head> and the JSON-LD.

This is a direct fix for the exact problem REQ-10 is trying to solve: Product/Offer/AggregateRating schema that's clean, complete, and not fighting another plugin for the same tag.

Solves REQ-10 directly
02

Real granularity per variant

Today's 20 lp-obd-* pages are one template with variables swapped in. With agentic generation, each brand×country page could carry genuinely distinct content — real error-code examples for that brand, brand-specific screenshots, community testimonials — instead of a {{BRAND}} find-and-replace.

This is the gap in REQ-10.3 as currently scoped: the proposed content block is still a template with blanks filled in, not truly differentiated content.

Beyond REQ-10.3
03

Performance

Elementor is heavy — render-blocking CSS/JS and builder overhead on every load. A well-built flat-file PHP page can be close to static.

That helps Core Web Vitals for traditional SEO, and likely helps crawl efficiency for AI bots, which work with a limited crawl budget per site.

Core Web VitalsAI crawl budget
04

Agentic iteration speed

If the system genuinely supports page generation and updates by agent, we could test content variants at a speed a manual Elementor workflow can't match.

Worth flagging

These four points are the upside case only. Before acting on any of this, we'd want to weigh it against migration risk on pages that already convert — tracking parity, SEO/Ads equity, and who else can maintain the system day to day.
